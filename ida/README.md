# minirubik on RV32I: IDA* with pattern databases

An optimal solver for the 2×2×2 cube that runs on Ripes. As the assignment's
precomputation rule asks, the transition and heuristic tables are built on
the host and linked as read-only data; only the search runs on the target.
Design, measurements and analysis are in the
[HackMD note](https://hackmd.io/9dUgyW8_SDy4kCeemswbow).

```
host                                                    target (Ripes)
build.c + gen_tables.c ──make──▶ tables.s ─────────────▶ asm/: the RV32I assembly search
                                 tables_ripes.s           the same bytes, for Ripes' assembler
                                 tables.c ──▶ solve, verify, rv32/ (the gcc reference)
```

## Files

| File | Runs on | What |
| :--- | :--- | :--- |
| `tables.h` | both | the data contract: table shapes, coordinates, indexing, move order |
| `cube.h` | both | the cube model; `source`, `twist` and the rank encoding are solver.c's |
| `build.c`, `build.h` | host | builds every table (level-sweep BFS) |
| `gen_tables.c` | host | writes `tables.c`, `tables.s` and `tables_ripes.s` from one build |
| `search.c`, `search.h` | target | IDA* over the tables; a loop by default, `DFS=recursive` for the recursive form of tag `stage3-c` |
| `solve.c` | host | command-line front end, same input format as solver.c |
| `verify.c` | host | exhaustive check of the tables and the search |
| `rv32/` | Ripes + host | the C search on Ripes and its host checker; `baseline/` runs the original solver.c |
| `asm/` | Ripes + host | the RV32I assembly search, with the LED renderer |
| `stage1/` to `stage4/` | Ripes + host | the programs and raw data behind the note |

`tables.c`, `tables.s` and `tables_ripes.s` are generated by `make`; do not
edit them.

## Build and run

```sh
make                       # tables, gen_tables, solve, verify
./solve 21345671111111     # moves on stdout; length and node counts on stderr
make quick                 # table checks on all states, IDA* on every 97th (about 2 s)
make check                 # every check on all 3,674,160 states (about 40 s)
make PDB=2                 # two PDBs only; files get a 2 suffix
make check DFS=recursive   # the recursive search; files get a _rec suffix
make -C rv32 verify        # the C search on Ripes, checked on the host
make -C asm verify         # the assembly on Ripes, checked on the host
make -C asm verify PROC=RV32_5S   # the same on the 5-stage pipeline
make -C asm check-render   # every LED frame against an independent 3-D model
```

`rv32/` and `asm/` need the xPack `riscv-none-elf-gcc` toolchain on `PATH`;
versions are in `ENVIRONMENT.md`. The run over all 2,644 distance-11 states
is in `stage4/README.md`.

## Table files

- `tables.s` puts the tables in `.section .rodata` for GNU as.
  `tables_ripes.s` holds the same bytes in `.data`, since Ripes' built-in
  assembler knows only `.text`, `.data` and `.bss`. Nothing writes them.
- Halfword tables come first, then byte tables, then `c4_row`, whose entries
  are addresses into `c4_h` (`.word c4_h+840`): Ripes' assembler resolves
  only labels defined earlier.
- `.equ` lines give each table's row stride in bytes (`PERM_Q_ROW`,
  `ADD81_ROW`, …), and the header lists each table's FNV-1a checksum.

## Checks

`make check` runs `verify` over every state:

0. the linked tables equal a fresh build;
1. the BFS depth histogram matches report.md;
2. coordinate moves match real cube moves;
3. every PDB is full and 0 at the goal (H2);
4. h is admissible and consistent (H1);
5. every answer is optimal and replays to solved (H3).

On Ripes, the assembly replays each answer on the cube model and compares
its length with the expected one (T5, T6), and `rv32/check_ripes` checks
every answer again on the host. `make -C asm verify PROC=RV32_5S` repeats
the cases on the pipeline model (T7). No table is nibble-packed, so H4 does
not apply.
